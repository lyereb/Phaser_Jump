# 挑战结算页面

## 使用与设计

失败后角色落出屏幕，游戏会停止当前局并自动切换到独立的“挑战结算”页面。旧的“掉下来啦／本次高度／点一下再冲”文字及全屏点按重开行为已删除。

页面沿用返回确认窗口的卡通风格：城市渐变背景加暗色遮罩、奶油色圆角卡片、暖色描边与粉色结束标记。中心用大号数字突出本次高度，金币奖励单独分区展示，堆叠与完美叠放统计并列显示。底部黄色主按钮为“重新挑战”，浅粉色次按钮为“返回主菜单”。长数字会自适应缩放，竖屏与横屏都能完整看到卡片和按钮。

| 信息 | 统计口径 |
| --- | --- |
| 本次高度 | 当前局结束时的真实计分米数，保持原有普通／完美计分规则 |
| 本局获得金币 | 结束余额减去本局开始余额，不把以前已有的金币算成新收益 |
| 堆叠盒数 | 成功加入当前堆叠的盒子总数，不含初始地面，包含弹簧自动叠出的十盒 |
| 完美叠放 | 本局居中完美叠放的盒数，包含弹簧自动居中的十盒，不等同于人物起跳次数 |
| 金币余额 | 当前钱包的累计金币，继续按原有 CoinWallet 逻辑保存 |

## 两种选择

“重新挑战”直接开始新局，将本局高度、堆叠与完美统计清零，checkpoint 从50米开始，护盾和弹簧状态重置；累计金币保留，新局的金币收益从新起始余额计算。单击重试不会穿透为起跳。

“返回主菜单”直接打开主菜单。结算时旧局已经结束，不再增加一次退出确认。空白背景、统计文字、右键以及未按下按钮就直接释放均不触发重开或退出；快速重复按钮事件只处理一次选择。

旧局停止时，盒子、角色、道具特效与计时器按场景生命周期清理，游戏背景音乐停止，不会在结算页后方继续运动或发放奖励。游戏进行中右上返回的确认暂停窗口仍然保留，两套流程互不残留。

## 修改文件

| 文件 | 修改 |
| --- | --- |
| `src/game/scenes/GameOver.ts` | 重写模板结算场景，显示真实统计、响应式卡片及两个明确按钮 |
| `src/game/scenes/Game.ts` | 记录每局金币起始余额与完美叠放数，失败后传递一次结算快照并停止旧局；删除旧失败文字及空白点按重开 |
| `vite/config.dev.mjs` | 排除临时工作、输出和工具日志目录的监听，避免Windows备份文件占用导致预览EBUSY中断 |

结算UI复用现有场景和背景，不需要新生图资源。后续弹簧计分已修复为整次固定10米，自动十盒保留完美叠放统计但不套用连击加分；checkpoint改为实体触碰即爆袋。道具概率、金币奖励、弹簧物理、护盾和AI图片未变。

## 验证

TypeScript类型检查和生产构建通过，生产JS包确认不再包含旧失败提示。11项结算真实场景测试、11项返回确认场景回归、12项道具规则、6项弹簧弹道和14项checkpoint逻辑测试全部通过，共54项相关检查。

覆盖零分结算、普通和完美金币收益、本局金币隔离、重试清零并保留余额、连击加分、弹簧十盒统计、旧局清理、防误点与重复结算、返回菜单、原暂停流程衔接、竖屏／横屏及大数字排版。两个结算按钮也已用真实鼠标点击验证。

验证使用独立QA金币存储键，不改变正常游戏金币。结算测试页、结果记录和修改前备份位于 `.work/settlement/`；原确认测试仍位于 `.work/return-confirm/`，不进入生产构建。

刷新 `http://127.0.0.1:8080/`，开始挑战并失败即可看到新页面。
