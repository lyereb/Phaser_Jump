# 返回主菜单确认窗口

## 使用方式

刷新 `http://127.0.0.1:8080/`，开始游戏后点击右上角的房子图标。现在不会立即返回主菜单，而是打开“返回主菜单？”确认窗口，并暂停本局。

| 操作 | 结果 |
| --- | --- |
| 继续游戏 | 关闭窗口，从原位置和状态立即继续，不额外起跳、不重新开始 |
| 返回主菜单 | 结束并清理当前局，打开主菜单；已获得金币仍保留 |
| 右上角关闭图标、键盘 Escape | 与“继续游戏”相同 |
| 点击卡片外的遮罩 | 不关闭、不退出，等待明确选择 |

窗口提示“返回后，本局挑战将结束，已获得的金币会保留”，并显示本次高度。继续游戏采用醒目的黄色主按钮，返回菜单采用浅粉色次按钮。奶油色圆角卡片、暖色描边和暗色半透明遮罩与现有卡通游戏风格一致；使用原生 Phaser 图形与文本，不需要额外生图或下载素材。

## 暂停范围

使用独立 `ReturnConfirmation` 场景显示窗口，同时暂停 `Game` 场景。因此角色运动、移动盒子、弹簧十盒进场、镜头跟随、角色动画、金币／护盾／checkpoint 特效和游戏计时器不会继续推进。背景音乐单独暂停；继续时恢复同一条音轨，不重新播放。

继续游戏时清零固定步余量并重新同步 TweenManager 的时间基准，不把用户停留在窗口的时间补算给角色或特效。窗口按钮在同一指针按下并释放时才生效，遮罩和输入状态阻止穿透；反复开关、双击与取消后再次点击返回都能正常工作。

确认返回主菜单会停止游戏场景并清理本局对象。弹簧途中退出时，旧批次十盒与特效一并销毁；新局不继承护盾、弹簧或暂停状态，已有金币仍按原来的钱包逻辑保留。失败后已改为独立结算页面，旧局停止；结算页提供“重新挑战”和“返回主菜单”，不再显示旧结束文字或额外返回确认窗口。

## 修改文件

| 文件 | 用途 |
| --- | --- |
| `src/game/scenes/ReturnConfirmation.ts` | 确认窗口、响应式布局、两种选择、关闭和 Escape |
| `src/game/scenes/Game.ts` | 打开窗口、暂停整局、原状态恢复、确认返回和清理 |
| `src/game/returnButton.ts` | 取消后可再次点击返回，避免原来的一次性退出锁 |
| `src/game/main.ts` | 注册独立确认场景 |
| `src/game/audio.ts` | 暂停和恢复原背景音乐 |

只新增返回确认流程，没有改动道具概率、金币收益、护盾规则、弹簧高度、计分或 AI 素材。当前项目的右上按钮已是返回主菜单按钮，没有重新引入旧暂停按钮。

## 验证结果

TypeScript `tsc --noEmit` 与生产构建通过。11项真实 Phaser 场景测试覆盖整局和特效冻结、计时器冻结、继续与再次打开、输入防穿透、Tween恢复不跳帧、弹簧续接固定10米与实体checkpoint触碰、关闭和Escape、结算衔接、菜单退出清理、金币保留、外部重开及窄屏／横屏布局。

另外回归了12项道具规则、6项弹簧弹道与14项checkpoint纯逻辑测试，合计43项相关检查。实际鼠标点击已验证“右上房子 → 确认窗口 → 继续游戏”和“右上房子 → 确认窗口 → 返回主菜单”。验证页使用独立金币存储键，不影响正常游戏金币。

测试页、结果记录及相关修改前备份保留在 `.work/return-confirm/`，不进入生产构建。
