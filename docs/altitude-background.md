# 局内城市到月球：按0～500米推进的背景

## 是否需要一张超级长图？

不需要。本次采用分段图片与透明渐变重叠，在程序中形成一条虚拟的纵向长背景。这样生图时每张只需普通竖图分辨率，运行时也不会把整条背景合并成超过手机显卡纹理尺寸限制的大图片。

现有 `public/assets/Obj/ingame_bg.png` 城市图保留、不覆盖。新增三张1440×2560母图，正式运行资源归一化到720×1280：`public/assets/Altitude/clouds.png`、`atmosphere.png`、`moon-space.png`。每个上方段底部24%添加透明渐变，覆盖在下方段的不透明顶部上，避免硬接缝或透明黑洞。四张图按城市、云层、大气层、月球太空的顺序绘制。

母图保留于 `.work/altitude-background/raw/`；`scripts/prepare_altitude_background.py` 可重新生成正式资源，需要Pillow。新增资源共约2.23MiB。背景只包含四个固定图像，不按米数不断增加对象或动态分配长纹理。

## 米数与画面

完整旅程按 `progress = clamp(本局米数 / 500, 0, 1)` 映射。0米以现有城市画面开始，随后云层进入、城市下移；中段穿过云层与蓝色大气弧光；高段进入大气层外的深色星空，最后出现月球。500米达到最终太空月球构图，之后即使成绩继续增长，背景仍保持终点画面。

这是将城市到月球的视觉旅程压缩到游戏的500米内，并非真实大气层的科学高度比例。不同阶段是连续移动和叠接，不是突然切换场景，也不是每次起跳播放一段动画。

按HUD显示的本局真实成绩推进，普通落地、Perfect连击与弹簧所得米数都沿用原计分逻辑。角色实际起跳或下落高度不用于移动背景，因此不会随单次跳跃上下晃动。成绩增加时，背景位置以0.65秒时间常数指数平滑追到目标；普通起跳期间没有获得新成绩，就不产生额外背景位移。未改动计分、道具、难度、角色或HUD功能。

## 失败、暂停与全景

撞击击飞和踏空两条失败入口都立即冻结当前已显示的背景进度。即使先前有尚未完成的平滑推进，也不会在失败后继续追到目标或退回城市。掉落、等待、900毫秒全景镜头缩放、结算及隐藏结算界面时，背景继续保持冻结。

背景使用零滚动系数的独立容器，并以主相机缩放的倒数补偿显示大小，固定在屏幕中心。独立审查发现极端调速下前一次护盾震动可能残留至失败，现已在背景自身渲染前抵消当前震动偏移，不全局停止相机震动，角色和盒子的原有受击反馈不变。

原返回确认弹窗暂停Game时，不推进背景；继续游戏后从原进度继续。重新开局会重新创建进度模型，回到城市；退出销毁背景容器及其子图。窗口大小变化按原进度重排而不重新开始。最终月球段根据实测纵向锚点修正宽屏裁切，常见横屏尺寸下不会被屏幕上边缘裁掉。

## 源码与可调参数

`src/game/altitudeBackgroundModel.ts` 负责映射、平滑、冻结与分段布局；`src/game/altitudeBackground.ts` 负责图片容器和镜头补偿。原 `scenes/Preloader.ts` 加载新资源，`scenes/Game.ts` 接入背景创建、更新、失败冻结、布局与销毁，正式入口不变。

在模型的 `ALTITUDE_BACKGROUND` 中，`endMeters: 500` 决定整段旅程的终点。若将来希望到1000米才看到最终月球，可改为1000。`smoothingSeconds: 0.65` 控制追随速度，改为0.9或1.2会更缓慢；该平滑仅在正常游戏中运行，不影响失败冻结。`overlap: 0.24` 必须与资源转换脚本的OVERLAP同步，不建议只改其中一个。
