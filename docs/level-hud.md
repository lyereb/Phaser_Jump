# 1000米左侧竖向进度与角落HUD

## 最终布局

金币固定左上，以金色图标和描边数字直接显示在场景上，不再放进独立深色框。原红屋顶房子菜单固定右上，点击仍先打开退出确认并暂停，选择继续恢复原局。

进度改为左侧竖条。奶油色轨道、绿色填充、小骑手标记与终点旗帜延续原卡通风格，随着真实米数由下向上平滑推进。只显示 **250、500、750、终点1000米** 四组标记，没有当前米数、百分比、剩余距离或额外标题。

当前米数恢复原 `UI/letters.png` 的黄色艺术字，放回屏幕偏上位置；正常0～1000米保持原字号与原位置。极长数字在必要时少量缩放，避免覆盖左侧进度文字。起跳提示和开发调试入口避开角落控件，所有UI固定于屏幕，不随世界镜头移动。

## 到达终点之后

默认目标为1000米。达到后竖条填满，小骑手停留在终点；后续计分不再创建进度移动动画。**角色仍可以继续跳，真实米数与艺术字继续增加，不自动结束、不切关，也不把成绩截断在1000米。**

例如1000米再完美落地一次，艺术字显示1002，竖条仍停在终点；1200米时艺术字显示1200，进度仍是满条。若之后失败，结算显示真实1200米，而不是1000米。

普通1～5米计分、弹簧整次固定10米、金币、一次性护盾、实体触碰checkpoint以及失败结算没有改变。暂停冻结竖条与标记动画，继续原状态恢复；重开进度与艺术字归零，金币保留。

## 配置和代码

默认目标在 `src/game/levelProgress.ts` 的 `LEVEL_GOAL_METERS = 1000`。进度模型只负责显示比例与封顶，不改分数或结束场景。`gameHud.ts` 负责左侧竖条和角落布局；`letters.ts` 复用原艺术数字；`Game.ts` 在真实计分入口同步两种显示。

金币区、竖条及终点文字都属于UI触摸区域，点击不会穿透起跳，场景其他区域仍可正常跳跃。菜单保留原确认窗口。

## 验证与试玩

TypeScript类型检查和最终生产构建通过。13项新进度模型测试、10项真实竖条场景回归通过；另回归14项checkpoint、12项道具规则与6项弹簧弹道，共55项检查。验证覆盖250至1000的向上比例、真实1000→1002落地、1200米继续展示及结算、原艺术字帧、金币保留、角落和竖条点击防穿透、终点文字边缘、相机滚动、暂停恢复、竖屏横屏和重开。

已另用真实鼠标验证“右上房子→退出确认→继续游戏”，恢复后艺术字1200与满进度保持不变。全部验证使用独立QA金币键，不修改正常游戏余额。

刷新 `http://127.0.0.1:8080/` 后开始挑战即可体验。验证页和中间横向样式备份保留在 `.work/level-hud/`，不进入生产构建。游戏素材全部复用，没有新生图、没有更换引擎，也没有发布网站。
