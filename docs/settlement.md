# 挑战结算页面

## 使用与设计

失败后先让角色按原镜头落出画面，等角色完全掉出下方后再等待1秒，才开始原有900毫秒摄像头全景缩放。缩放完成后仍展示1秒完整堆叠，再覆盖“挑战结算”页面。人物掉落与摄像头缩放不再同时进行。旧的“掉下来啦／本次高度／点一下再冲”文字及全屏点按重开行为仍保持删除。

页面沿用返回确认窗口的卡通风格：真实堆叠全景加暗色遮罩、奶油色圆角卡片、暖色描边与粉色结束标记。中心用大号数字突出本次高度，金币奖励单独分区展示，堆叠与完美叠放统计并列显示。底部黄色主按钮为“重新挑战”，浅粉色次按钮为“返回主菜单”。长数字会自适应缩放，竖屏与横屏都能完整看到卡片和按钮。

结算卡片左上方新增“隐藏”按钮。点击后暂时隐藏整张卡片及遮罩，直接查看刚才真实的完整堆叠；再点击屏幕任意区域只恢复同一张结算卡片，不重新开始、不继续旧局。允许反复隐藏和显示；隐藏状态下窗口变化仍重新适配全景。查看全景时人物、待进场盒、游戏HUD和庆祝特效不遮挡已叠好的盒子。独立QA直接启动且没有旧局底图的结算页面仍使用城市背景，不显示无底图的隐藏按钮。

| 信息 | 统计口径 |
| --- | --- |
| 本次高度 | 当前局结束时的真实计分米数，保持原有普通／完美计分规则 |
| 本局获得金币 | 结束余额减去本局开始余额，不把以前已有的金币算成新收益 |
| 堆叠盒数 | 成功加入当前堆叠的盒子总数，不含初始地面，包含弹簧自动叠出的十盒 |
| 完美叠放 | 本局居中完美叠放的盒数，包含弹簧自动居中的十盒，不等同于人物起跳次数 |
| 金币余额 | 当前钱包的累计金币，继续按原有 CoinWallet 逻辑保存 |

## 结算操作与生命周期

“重新挑战”直接开始新局，将本局高度、堆叠与完美统计清零，checkpoint 从50米开始，护盾和弹簧状态重置；累计金币保留，新局的金币收益从新起始余额计算。单击重试不会穿透为起跳。

“返回主菜单”直接打开主菜单。结算时旧局已经结束，不再增加一次退出确认。空白背景、统计文字、右键以及未按下按钮就直接释放均不触发重开或退出；快速重复按钮事件只处理一次选择。

结算期间旧局暂停而非立即销毁，只渲染已冻结的真实全景，游戏背景音乐停止，不会继续运动、发放奖励或响应起跳。隐藏结算不会恢复旧局。只有选择重新挑战、返回菜单或结算场景被外部关闭时，才清理旧局节点与计时器。重试先销毁旧局再创建新局，结算退出回调不会重复停止刚创建的新局。原游戏进行中右上返回的确认暂停窗口仍然保留。

## 修改文件

| 文件 | 修改 |
| --- | --- |
| `src/game/scenes/GameOver.ts` | 显示真实统计、响应式卡片、重试/菜单按钮；新增隐藏/点击恢复，透明覆盖冻结全景并在退出时清理旧局 |
| `src/game/scenes/Game.ts` | 记录每局金币起始余额与完美叠放数，掉落结束后等待1秒再缩放，结算快照仅传递一次；保留暂停的真实堆叠底图 |
| `vite/config.dev.mjs` | 排除临时工作、输出和工具日志目录的监听，避免Windows备份文件占用导致预览EBUSY中断 |

结算UI复用现有场景和背景，不需要新生图资源。后续弹簧计分已修复为整次固定10米，自动十盒保留完美叠放统计但不套用连击加分；checkpoint改为实体触碰即爆袋。道具概率、金币奖励、弹簧物理、护盾和AI图片未变。
